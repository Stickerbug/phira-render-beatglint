# 异步唤醒修复与验证

## 修复内容

headless renderer 的 `prpr` 原来在两个路径使用 Tokio 后台任务：

- `prpr::ext::spawn_task`；
- `ExternalFileSystem::load_file`。

`prpr-macroquad` 只逐帧轮询 future，headless 文件加载路径中 Tokio worker 完成时发出的外部 wake 会触发：

```text
macroquad does not support waking futures
```

当前 `main` 将这两个 headless 文件加载路径改为已有的 `thread_as_future`。线程只写入共享结果，主循环继续轮询；修复目标不涉及谱面、音符、时间轴或图像输出协议；在本次 Demonkin segment/resident 对照中，frame bytes 保持一致。`Task::new` 等其他完整应用路径仍保留自己的 Tokio 生命周期，不能把这次修复泛化为整个 `prpr` 无 Tokio wake。

## 运行验证

同一 Demonkin 输入、皮肤、资源和 640×360/30 fps 设置下：

| 模式 | 结果 | stderr panic | 输出对照 |
|---|---|---:|---|
| segment，30–31 s | 返回码 0，1.000 s | 0 | SHA 与未修复版相同 |
| residentWindows，30–31 s、31–32 s | 返回码 0，两个 1.000 s | 0 | 两个窗口 SHA 与未修复版相同 |

未修复版和修复版的画面字节一致，修复只清除了异步唤醒诊断；这个结论限定于上面列出的 bounded smoke 输入和窗口。完整 Phira/AppImage 仍需单独记录，因为它可能使用不同的构建和依赖版本。

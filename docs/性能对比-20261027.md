# 性能对比

以下只记录已经完成的样本，不是跨硬件基准。输入和输出不随公开仓库发布。

| 测试 | 条件 | 旧 | 新 | 结果 | 结论边界 |
|---|---|---:|---:|---|---|
| 编译 profile | Credits，320×180，10 fps，5 帧 | `release`：0.767 s | `release-fast`：0.513 s | elapsed 约减少 33.1%；输出 SHA 相同 | 只适用于该小窗口和该机器 |
| 整曲混音与渲染 | Credits，320×180，1 fps，107 帧，6 次冷启动 | `Done` 中位 3.94 s（3.05–5.06） | `Done` 中位 3.27 s（2.93–4.12） | 中位耗时约减少 17.1%；最终音频解码 SHA 相同；最大 RSS 均约 244 MiB | 当前累积优化相对旧基线的单机低帧率 smoke，不能外推到 30 fps、其他分辨率或其他 GPU |
| 整曲音频混音 | 8192-frame 分块 | 整段缓冲 | 分块写入 | 873,310 个 stereo samples：平均差 0，最大差 0，完全一致 | 没有受控耗时 A/B，不能宣称变快 |
| 像素读回 | full 三重 PBO、bounded RGBA（4 bytes/pixel） | 尾部可能丢帧；bounded 每帧分配 | drain 尾部、复用缓冲，并按渲染目标原生 RGB8 使用 RGB24（3 bytes/pixel） | 首尾帧完整；任意宽度逐像素一致；1920×1080/30fps 配对样本总帧循环 14.75 s → 10.45 s（约 29.1%） | 单机单次配对，受 Mesa/CPU 调度影响；不能外推所有 GPU |

## 测量条件

| 项目 | 值 |
|---|---|
| 系统 | Linux Xorg/Mesa |
| 工具链 | Rust 1.99.1 |
| 输入 | Credits 前缀，SHA-256 `59bad2003abb894bc7d2b2267f4c0282f213de5dae3ce1ee6d5d64c9cf6bc4ef` |
| 历史记录 | `c61711c`、`b267838` 及绑定的渲染器提交 |
| 整曲样本基线 | 二进制 SHA-256 `77eab529f37fc3a2f2c48845b73de03869ec12bb58a443b7797b07cc7c80faf2` |
| 整曲样本当前构建 | 二进制 SHA-256 `fec46f45716b7497eddbb08a89c60118d3d56b6a2882dae03518e05889a1b87e` |
| 整曲音频输出 | 两种构建解码后的 MP3 PCM SHA-256 `b305fed5e818cfb3c9c3e6437bbf10f076620db63e506f7e108f0daa635bdf67` |

这些数字不能外推到其他硬件、不同分辨率、30 fps 生产渲染或完整 Phira 视觉 parity。

## RGB24 等价性检查

| 检查 | 结果 |
|---|---|
| 320×180 单帧，旧 RGBA vs 新 RGB24 | 解码后 RGB 像素 `max diff=0`、不等像素数 `0` |
| 321×180 单帧（非四字节行宽），旧 RGBA vs 新 RGB24 | 解码后 RGB 像素 `max diff=0`、不等像素数 `0` |
| 1920×1080、30fps、2 秒 bounded segment | 两个 MP4 SHA-256 均为 `8715f814a7acea75826baaa35cafd34ea75e9f5f328a17b4cbca00b74a98aa01` |

RGB24 只减少 GPU→CPU→FFmpeg 的像素传输量，不改变场景绘制、编码码率、音频或读谱语义。`GL_PACK_ALIGNMENT=1` 用于保证任意输出宽度的行连续性。
